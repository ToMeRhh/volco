# Playing Indicator Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Media buttons' screens show bouncing equaliser bars while their app plays and the same bars frozen while it is paused or stopped.

**Architecture:** Two new icon ids from the existing icon pipeline (`draw_icons.py` → PNGs → `gen_assets.py` → C++ tables, C# enum, simulator `icons.js`). Icon 17 has 4 frames; `volco_render` picks a frame from the screen's scroll clock, so the firmware animates on its own with no protocol change. `screens.cpp` pushes only the changed 8×8 tiles to a panel. The app sends the new ids from `ControllerDisplay` and animates them in the settings preview.

**Tech Stack:** C++17 (PlatformIO, Unity native tests, U8g2), Python 3 + Pillow ≥ 10, C# / .NET 8 (xUnit, Avalonia 12 headless), plain JS + `node --test`.

**Spec:** `docs/design/playing-indicator.md`

**Note (after rebasing onto PR #94):** `main` took icon id 17 for `error`, so the equaliser is 18 and the still bars 19 (render golden payload bytes `0x12`/`0x13`). The ids 17/18 below are as originally planned.

## Global Constraints

- No protocol change: the `Screen` frame (`0x84`) and the protocol version stay as they are.
- Icon ids are stable: append to `manifest.txt`, never insert. New ids: `17 equalizer Equalizer` (4 frames), `18 equalizerstill EqualizerStill` (1 frame), neither offered on the Devices page.
- Stems are the C# name in lower case (`ScreenIcons.Bitmap` builds file names from `icon.ToString().ToLowerInvariant()`). A multi-frame icon's files are `<stem>_0.png` … `<stem>_<n-1>.png`; a one-frame icon's file is `<stem>.png`.
- Frame period: `kIconFrameMs = 180` (C++), `ScreenIconSets.FrameMs = 180` (C#), `frameMs: 180` (simulator), all emitted by `gen_assets.py` from one Python constant.
- Frame shown = `(since / 180) % frames`, where `since` is the value `renderScreen` already receives (scroll clock; 0 during a slide).
- The animation runs at normal and dimmed brightness and stops only while the panels are off (existing `screens_tick` behaviour; no setting).
- Generated files (`volco_icons.{h,cpp}`, `ScreenIcon.g.cs`, `icons.js`) are never hand-edited; change `gen_assets.py` and rerun `python3 firmware/tools/gen_assets.py`.
- Git in this worktree: use `/usr/bin/git` (plain `git` is refused).
- **Do not run `dotnet` locally.** C# is verified in CI: push the branch, then `gh workflow run build.yml --ref worktree-playing-anim` and `gh run list --branch worktree-playing-anim --limit 3`. Never pass `run_build=true`.
- Firmware tests run locally: `cd firmware && ~/.platformio/penv/bin/pio test -e native`. Simulator tests: `cd tools/simulator/test && npm ci && node --test`.

## Review Focus

1. **A slide into or out of a Playing screen**: both sides render with `since = 0`, so the bars hold frame 0 during the slide and start moving after it. Pinned by Task 3's `test_animated_icon_frames` (since 0 = frame 0) and the goldens.
2. **An unknown icon id with a large `since`**: still falls back to generic, and the frame arithmetic never reads past the table. Pinned by Task 3 (`unknown icon at since 720 == generic at since 0`).
3. **Muted flag on an animated icon**: the slash is drawn over every frame. Pinned by Task 3.
4. **The first push after boot and a pixel shift**: they change the whole frame, so the dirty box must be all 16×8 tiles (otherwise a panel keeps stale pixels). Pinned by Task 4 (`all different → {0,0,16,8}`).
5. **The settings preview after the screen changes away from Playing, or after the control leaves the window**: the timer must stop (no leaked timers, no frame index carried into another icon). Pinned by Task 6.

TileBox changedTiles(const Canvas& a, const Canvas& b) {
  int x0 = 16, y0 = 8, x1 = -1, y1 = -1;
  for (int page = 0; page < Canvas::kHeight / 8; page++)
    for (int tx = 0; tx < Canvas::kWidth / 8; tx++) {
      int i = page * Canvas::kWidth + tx * 8;
      if (memcmp(a.buf + i, b.buf + i, 8) == 0) continue;
      if (tx < x0) x0 = tx;
      if (tx > x1) x1 = tx;
      if (page < y0) y0 = page;
      if (page > y1) y1 = page;
    }
  if (x1 < 0) return {0, 0, 0, 0};
  return {(uint8_t)x0, (uint8_t)y0, (uint8_t)(x1 - x0 + 1), (uint8_t)(y1 - y0 + 1)};
}

    private static readonly Dictionary<(ScreenIcon, int), Bitmap> Cache = new();

    /// <summary>The 1-bit OLED art, for the screen preview only: it is crisp at 1:1 pixels and
    /// pixelated at any other size. <paramref name="frame"/> picks an animated icon's frame.</summary>
    public static Bitmap Bitmap(ScreenIcon icon, int frame = 0)
    {
        // A hand-edited config can hold any number; there is no PNG for an undefined one.
        if (!Enum.IsDefined(icon)) icon = ScreenIcon.Generic;
        var frames = ScreenIconSets.FrameCount(icon);
        frame = ((frame % frames) + frames) % frames;
        lock (Cache)
        {
            if (!Cache.TryGetValue((icon, frame), out var bitmap))
            {
                // File stems are the lower-case enum names (manifest.txt: StudioMic -> studiomic);
                // an animated icon's frames are <stem>_0.png, <stem>_1.png, ...
                var stem = icon.ToString().ToLowerInvariant();
                var file = frames > 1 ? $"{stem}_{frame}" : stem;
                var uri = new Uri($"avares://Volco.App/Assets/Icons/{file}.png");
                Cache[(icon, frame)] = bitmap = new Bitmap(AssetLoader.Open(uri));
            }
            return bitmap;
        }
    }
